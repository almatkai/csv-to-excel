# Convert CSV to Excel — Native V2

Offline Rust replacement beside unchanged V1. Source: `718b9ca0b42e00be968491064310ac6e5bc76a93`; original extension and icon by **VictoRD11**. See [NOTICE](NOTICE.md) for exact provenance and licensing.

`src/` is a standalone Rust library (MSRV 1.85); `adapter.rs` is the concrete compiled-in beta adapter. Conversion uses no JavaScript, Bun, network, clipboard bridge or external application. The source really creates an XLSX file, not TSV or HTML. Node is used only for validation.

The one `index` command presents CSV File / Convert. It selects the first file, validates lowercase `.csv` and a regular non-symlink file, and writes `<name>.xlsx` beside it. An existing destination selects one random suffix in 1..999; a second collision is an error. Every cell stays text, including formulas, numbers and dates. The delimiter is always comma; record delimiter detection follows csv-parse. Unquoted fields are trimmed, the first record supplies object keys, duplicates retain their last value, numeric keys use JavaScript key order, and `__proto__` string assignment is ignored. Header-only input produces the same empty workbook as V1. BOM is retained, not stripped. Malformed records return errors.

Beta's webview FilePicker can return just a basename. **Actions → Choose CSV File** uses the existing Tauri dialog plugin to obtain a real local path. Basename-only paths are rejected explicitly. The picker callback is an OS boundary, never a conversion fallback. Native dialogs were tested with stubs, not opened. Source HUD/toast/pop-to-root feedback is adapted to an error Form or success Detail with Back; there is no claim that beta provides those Raycast APIs. There are no preferences, launch arguments, clipboard/file-copy/open actions, saved history, storage or legacy migration to port.

File publication uses a native temporary sibling and atomic no-clobber persist to avoid partially written files and the V1 exists/write race. Computed XLSX bytes and the exact target stay bound in session state until acknowledged. An unconfirmed effect offers an explicit retry of those bytes; refresh/search never retry writes. Successful capabilities are consumed; Back restores the submitted file draft. Error/cancellation replies omit file values and callbacks to preserve newer local drafts; Back and native selection restore the bound draft explicitly. Failed publication can leave a complete destination if the OS completed the operation before reporting failure; retry never overwrites it. No automatic cleanup removes a user's destination.

Explicit limits: input 8 MiB, decoded parser input at most 24 MiB, 100,000 physical records, 250,000 cells, 16,384 columns, 32,767 UTF-16 code units per output cell, 64 MiB XLSX output, 128 selected paths and 32,768 UTF-8 bytes per path. Exceeding a limit returns an error, never truncated data. Conversion/publication is synchronous inside one adapter poll so cancellation cannot interrupt an acknowledged write before its state checkpoint; slow filesystem I/O may block that worker. OS dialog cancellation after session disposal cannot be forcibly dismissed through the pinned plugin API and remains desktop QA.

[Integration](INTEGRATION.md) documents vendoring, compiled dispatch/catalog/installation and rebuild. [Validation](VALIDATION.md) gives reproducible gates and honest platform gaps. JSON alone cannot install a Rust handler. Both manifest verification entries remain `not-run`.
